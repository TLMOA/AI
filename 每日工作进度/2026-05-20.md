## 4. 遇到问题

1. HBase Thrift 端口冲突
   - 问题：宿主机 `9090` 被 systemd 管理的服务占用，Docker 无法绑定 `9090:9090`。
   - 处理：将 HBase Thrift 宿主机端口调整为 `19090`，容器内保持 `9090`。

2. Docker Compose 旧容器状态影响端口映射
   - 问题：文件已改为 `19090:9090` 后，日志仍显示绑定 `9090`。
   - 处理：执行 `docker compose down`、删除旧 `hbase-thrift` 容器并强制重建，确认新配置生效。

3. Hadoop/Hive/HBase 镜像启动方式不一致
   - 问题：最初 compose 写法混用了其他 Hadoop 镜像风格，导致环境变量、入口命令、JAVA_HOME 不适配。
   - 处理：分别检查镜像内部路径、入口脚本和配置转换机制，调整 compose 写法。

4. 后端依赖安装到错误 Python 环境
   - 问题：初次安装依赖时装到了 conda/base 环境，而 systemd 后端实际使用 `/home/yhz/iot/.venv`。
   - 处理：定位 systemd 服务实际启动命令后，将依赖重新安装到正确虚拟环境。

5. `sasl==0.3.1` 编译失败
   - 问题：Python 3.13 下构建 `sasl` 报 `longintrepr.h` 缺失。
   - 处理：不再强依赖该包，改装 `thrift-sasl` 与 `pure-sasl`，满足当前 Hive/HBase 联调。

6. HDFS 列表接口误查 `/nifi`
   - 问题：前端旧数据库名字段仍传 `nifi`，后端将其当作 HDFS 路径，导致 `File /nifi does not exist`。
   - 处理：前端默认路径改为 `/`，后端兼容 `nifi` / `/nifi` 自动映射为 `/`。
