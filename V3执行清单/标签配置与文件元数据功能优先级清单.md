## 🟢 P0：必须实现（汇报前完成，阻塞主流程）

「数据库导出 → 文件上传 → 预览 → 手动/自动打标」端到端最短路径，少一项就跑不通。

| # | 模块 | 具体功能 | 对应章节 |
|---|------|---------|---------|
| P0-1 | **meta_json 工具模块** | 实现 `app/meta_json.py`：定义完整 schema、实现 `meta_path / write_meta / read_meta / has_meta / delete_meta` | §3.3.2 |
| P0-2 | **后端-导出接口** | 接收 `hasTag / tagColumn / tagName / tagRange`，写文件后落 `.meta.json`，按 `hasTag` 决定入普通/标签目录 | §5.1 |
| P0-3 | **后端-上传接口** | 同 P0-2，针对上传场景 | §5.2 |
| P0-4 | **后端-预览接口** | 通过 `read_meta()` 读取 meta，识别 `tagColumn`；新增列限制为 1 列 `tag`；返回值附带 `hasTag / tagColumn / tagName / tagRange` 摘要 | §5.3 |
| P0-5 | **后端-手动打标接口** | 标签值必须在 `tagRange` 内；输出新文件并写新 meta；同步更新 `tagColumn` 和 `tagName` | §5.4 |
| P0-6 | **后端-自动打标接口（基础）** | 支持多列规则 `tagRule`；输出列默认 `tag`；新文件写 meta | §5.5 |
| P0-7 | **前端-导出表单** | 新增「是否含标签」单选 + 标签列 / 标签名字 / 候选标签范围三个条件输入 | §4.1 |
| P0-8 | **前端-上传表单** | 同 P0-7 | §4.2 |
| P0-9 | **前端-预览编辑区** | 限制最多新增 1 列、新列名固定 `tag`、已存在 `tag` 列禁止再新增；优先用 meta 中的 `tagColumn` / `tagName` | §4.3 |
| P0-10 | **目录规则落地** | 无标签 → 普通目录 + `hasTag=false` + 必填 `tagRange`；有标签 → 标签目录 + `hasTag=true` + 必填 `tagColumn / tagName` | §6 |

**P0 验收口径（按 §7.1 跑过即可）：**

- [x] 导出 / 上传能填标签信息
- [x] 每个文件都有独立 `.meta.json`
- [x] 无标签文件有 `tagRange`、有标签文件有 `tagColumn` + `tagName`
- [x] 预览新增列限制为 1 列 `tag`
- [x] 自动打标支持多列规则
- [x] 打标结果文件进入标签目录

## 🎯 建议汇报主线（演示脚本，5–8 分钟）

按这条路径走能完整覆盖 P0：

```
1. 数据库导出
   选 hasTag=false → 填 tagRange=故障/预警/正常 + failedTag=故障
   → 落盘到普通目录 + 自动生成 .meta.json

2. 文件上传
   选 hasTag=true → 填 tagColumn=label + tagName=质量等级
   → 落盘到标签目录 + 自动生成 .meta.json

3. 在文件中心打开「导出文件」预览
   → 展示 hasTag=false / tagRange / failedTag
   → 点「手动打标」→ 选范围内标签 → 保存
   → 新文件入标签目录 + 新 .meta.json

4. 在文件中心打开「上传文件」预览
   → 展示 hasTag=true / tagColumn=label
   → 点「自动打标」→ 配置多列规则 → 执行
   → 新文件入标签目录 + 新 .meta.json（含 tagRule）

5. 调 GET /api/v1/training/files
   → 展示列表 + 强调「响应中不含 storagePath」
```
