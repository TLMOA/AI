# 零文件元数据方案：xattr + 加密存储

## 1. 目标

用 Linux 扩展属性（xattr）替代 `.meta.json` 独立配置文件，实现**磁盘上不存在任何额外的配置文件**，元数据通过加密嵌入数据文件的 inode 扩展属性中，对所有用户（包括 root）不可见。

## 2. 原理

```
传统方案：
  sensor_data.csv              ← 数据文件
  sensor_data.csv.meta.json    ← 配置文件（任何人都能看到）

本方案：
  sensor_data.csv
  │
  │  文件内容：正常的 CSV 数据，一行不多，一行不少
  │
  │  inode 扩展属性（完全不可见）：
  │  ┌──────────────────────────────────────┐
  │  │ user.meta     = AES-256-GCM 密文      │
  │  │ user.checksum = SHA-256 校验码        │
  │  └──────────────────────────────────────┘
  │
  └── ls、cat、文件管理器均看不到扩展属性
      只有 getfattr / os.getxattr() 能读取
```

### 2.1 关键特性

- **零额外文件**：每个数据文件不再需要一个同名 `.meta.json`
- **inode 级别附着**：元数据属于文件系统元信息，不属于文件内容
- **文件操作不感知**：改名、移动、复制（`cp --preserve=xattr`）自动跟随
- **加密存储**：即使 root 用 `getfattr` 读到，也是 AES 密文，无密钥不可解密
- **文件删除自动清理**：inode 释放时 xattr 同时销毁

## 5. 实现

### 5.1 依赖

| 模块 | 用途 | 来源 |
|------|------|------|
| `os` | `setxattr` / `getxattr` / `removexattr` / `listxattr` | 标准库 |
| `json` | 元数据序列化 | 标准库 |
| `hashlib` | SHA-256 完整性校验 | 标准库 |
| `hmac` | 常量时间比较 | 标准库 |
| `base64` | 编码密文 | 标准库 |
| `cryptography` | AES-256-GCM 认证加密 | `pip install cryptography` |

### 5.2 核心代码

```python
import os
import json
import hashlib
import hmac
import base64
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

# 密钥：32 字节，从环境变量读取，不落盘
# export META_XATTR_KEY="<base64 编码的 32 字节密钥>"
META_KEY = base64.b64decode(os.environ["META_XATTR_KEY"])
aesgcm = AESGCM(META_KEY)

XATTR_META = "user.meta"
XATTR_CHECKSUM = "user.checksum"


def write_meta(file_path: str, meta: dict) -> None:
    """写入加密元数据到文件的扩展属性。

    AES-256-GCM 认证加密：GCM 模式自带认证标签，无需额外 HMAC。
    不创建任何额外文件，磁盘上只有数据文件本身。
    """
    plaintext = json.dumps(meta, ensure_ascii=False, separators=(",", ":")).encode()
    nonce = os.urandom(12)                 # GCM 推荐 12 字节 nonce
    ciphertext = aesgcm.encrypt(nonce, plaintext, None)  # 密文 + 16 字节 GCM 认证标签
    payload = base64.b64encode(nonce + ciphertext)
    os.setxattr(file_path, XATTR_META, payload)

    # 存储明文 SHA-256 哈希用于快速一致性校验（磁盘位翻转检测）
    os.setxattr(file_path, XATTR_CHECKSUM,
                hashlib.sha256(plaintext).hexdigest().encode())


def read_meta(file_path: str) -> dict:
    """读取并解密文件扩展属性中的元数据。

    GCM 解密时自动验证认证标签，校验失败时抛出异常。
    """
    payload = base64.b64decode(os.getxattr(file_path, XATTR_META))
    nonce = payload[:12]                               # 前 12 字节
    ciphertext = payload[12:]                          # 剩余（含 16 字节 GCM tag）

    try:
        plaintext = aesgcm.decrypt(nonce, ciphertext, None)
    except Exception:
        raise ValueError("元数据 GCM 认证失败：文件可能被篡改")

    # SHA-256 二次校验（防御磁盘静默损坏）
    expected_hash = hashlib.sha256(plaintext).hexdigest()
    actual_hash = os.getxattr(file_path, XATTR_CHECKSUM).decode()
    if not hmac.compare_digest(expected_hash, actual_hash):
        raise ValueError("元数据 checksum 校验失败：数据损坏")

    return json.loads(plaintext)


def delete_meta(file_path: str) -> None:
    """删除文件的元数据扩展属性。"""
    for attr in (XATTR_META, XATTR_CHECKSUM):
        try:
            os.removexattr(file_path, attr)
        except OSError:
            pass


def has_meta(file_path: str) -> bool:
    """检查文件是否已有元数据。"""
    try:
        return XATTR_META in os.listxattr(file_path)
    except OSError:
        return False
```

### 5.3 受支持的 xattr 操作

| 操作 | 命令/行为 |
|------|------|
| 写入 | `os.setxattr(file, "user.meta", payload)` |
| 读取 | `os.getxattr(file, "user.meta")` |
| 删除 | `os.removexattr(file, "user.meta")` |
| 列举 | `os.listxattr(file)` → `["user.meta", "user.checksum"]` |
| 复制文件 | `cp --preserve=xattr src dst` |
| rsync 同步 | `rsync -X src dst` |
| tar 打包 | `tar --xattrs -cf archive.tar files/` |
| Docker 卷 | 默认支持，无需特殊配置 |
| 文件改名 | xattr 自动跟随（依附 inode，不依赖文件名） |
| 删除文件 | xattr 随 inode 自动释放 |

### 5.4 后端索引扫描改造

扫描逻辑从读取 `.meta.json` 改为读取 xattr：

```python
# 原来的扫描
for file_path in base_dir.rglob("*"):
    if file_path.name.endswith(".meta.json"):
        continue
    meta_path = Path(str(file_path) + ".meta.json")
    if meta_path.exists():
        meta = json.loads(meta_path.read_text())

# 改造后的扫描
for file_path in base_dir.rglob("*"):
    if not file_path.is_file():
        continue
    if not has_meta(str(file_path)):
        continue
    meta = read_meta(str(file_path))
    files[meta["fileId"]] = meta
```

### 5.5 密钥管理

```
密钥生成（一次性操作）：
  $ python -c "import secrets,base64; print(base64.b64encode(secrets.token_bytes(32)).decode())"
  c2VjcmV0LWtleS1mb3IteGF0dHItbWV0YS0zMmJ5dGVzAAAAAA==

写入 systemd 环境变量（只有 root 可读）：
  # /etc/systemd/system/iot-backend.service.d/xattr.conf
  [Service]
  Environment="META_XATTR_KEY=c2VjcmV0LWtleS1mb3IteGF0dHItbWV0YS0zMmJ5dGVzAAAAAA=="
```

**密钥丢失后果**：无法解密任何 xattr 元数据，需要重新扫描文件并重建元数据（columns、rowCount 等自动字段可重建，用户输入的 tagName、tagRange 等会丢失）。

**密钥轮换**：重新加密全部文件的 xattr，存量用旧密钥解密后新密钥加密写入。

### 6.2 攻击面评估

| 攻击方式 | 结果 |
|----------|------|
| 浏览器 URL 访问 | ❌ Nginx 不暴露数据目录 |
| API 调用 | ❌ 响应不含 storagePath |
| SSH `ls` / `cat` | ❌ xattr 不显示 |
| SSH `getfattr` 读取 | ❌ 看到密文，无密钥不可解 |
| 文件系统备份 | ❌ 默认 tar/rsync 不保留 xattr |
| 物理硬盘窃取 | ❌ 密文 + 密钥在环境变量中分离 |
| root 提权 + 读取 systemd env | ⚠️ 可获取密钥（运维管控层防范） |

### 6.3 与 .meta.json 方案对比

| 维度 | .meta.json | xattr + 加密 |
|------|:--:|:--:|
| 额外文件数 | N（每个数据文件一个） | 0 |
| 文件名依赖 | 强（必须同名） | 无（依附 inode） |
| 文件改名 | 需同步改 .meta.json | 自动跟随 |
| 复制/备份 | 必须同时复制两个文件 | `cp --preserve=xattr` |
| ls 可见 | 是 | 否 |
| cat 可读 | 是（明文） | 否（不属于文件内容） |
| 加密保护 | 无 | 有（AES-256-GCM） |
| 密钥依赖 | 无 | 需管理密钥 |
| 实现复杂度 | 低 | 低（cryptography 库一行加密） |
| Linux 独占 | 否 | 是 |

## 7. 从 .meta.json 迁移

对于项目中已有的 `.meta.json` 文件，执行一次性迁移脚本：

```python
import os
import json
from pathlib import Path

def migrate_all(base_dir: str):
    """一次性将全部 .meta.json 迁移到 xattr。"""
    base = Path(base_dir)
    for meta_path in base.rglob("*.meta.json"):
        meta = json.loads(meta_path.read_text())
        data_file = Path(str(meta_path)[:-len(".meta.json")])
        if data_file.exists():
            write_meta(str(data_file), meta)
            meta_path.unlink()  # 删除旧的 .meta.json
            print(f"已迁移: {data_file.name}")
```

## 8. 兼容性与风险

### 8.1 Linux 文件系统支持

| 文件系统 | xattr 支持 |
|----------|:--:|
| ext4 | 默认支持 |
| xfs | 默认支持 |
| btrfs | 默认支持 |
| NFSv4 | 支持 |
| tmpfs | 有限支持（重启丢失） |

### 8.2 风险与应对

| 风险 | 应对 |
|------|------|
| xattr 在 rsync/tar 时不保留 | 脚本中始终使用 `-X` / `--xattrs` 参数 |
| 密钥丢失导致元数据不可读 | 每日备份 xattr 到加密 tar，异地存储 |
| 文件系统不支持 xattr | 部署前检测，不支持时回退 `.meta.json` |
| 非 Linux 环境（开发机是 macOS） | 开发环境提供 fallback 实现，写入 `.meta.json` |

### 8.3 开发环境降级策略

```python
import sys

if sys.platform == "linux":
    # 生产环境：使用 xattr
    from app.meta_xattr import write_meta, read_meta
else:
    # 开发环境（macOS/Windows）：降级为 .meta.json
    from app.meta_json import write_meta, read_meta
```

核心亮点总结：

- **磁盘上零配置文件**：不会再有 `xxx.meta.json` 暴露在目录里
- **加密不可见**：即使 root 用 `getfattr` 强行读取，看到的也是 AES-256-GCM 密文
- **工业级加密**：基于 `cryptography` 库的 AES-256-GCM，自带认证标签，一行代码完成加密+防篡改
- **自动跟随**：文件改名/复制/移动，元数据不会丢
- **开发环境兼容**：macOS/Windows 上自动降级为 `.meta.json`，不影响日常开发
