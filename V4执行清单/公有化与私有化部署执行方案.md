**版本：v4.0**
**日期：2026-06-11**
**基于文档：**《AI模块综合执行方案（融合NiFi、联邦学习与双模部署）》

## 一、需求定义

### 1.1 公有化部署
工厂把通过我们网站规整好的训练数据，直接存放到**我们的 Ceph** 里。数据在我们自己的机器上，可以直接用于中心训练。

### 1.2 私有化部署
工厂把通过我们网站规整好的训练数据，存放在**工厂自己的 Ceph** 里。管理员通过内部管理页面切换用户并拉取数据到我们机器，再用于中心训练。

### 1.3 用户与工厂关系
每个用户就是一个工厂，用户名即工厂标识。一个工厂的 Ceph 上只有该工厂自己的数据，不存在多用户并存。

### 1.4 管理员权限
管理员登录内部管理页后，可通过顶部下拉菜单切换任意用户（公有化+私有化），查看该用户的 `nifi-data` 和 `real_nifi_data` 文件列表并执行拉取操作。

管理员本身也是一个"部署在公司的私有化用户"——他的 `ceph_endpoint` 指向公司本地路径（如 `/home/yhz/admin/`），其数据也同步到 `/home/yhz/admin/` 方便统一管理。

### 1.5 普通用户权限
普通用户（非管理员）登录后，在自己的"文件中心"页面可看到自己的 `nifi-data` 和 `real_nifi_data`，无论公有化还是私有化。**普通用户看不到内部管理页**。

### 1.6 各角色数据访问权限总览

| 角色 | 数据物理位置 | 本地文件系统直接查看 | 前端文件中心查看 | 管理员内部页查看 |
|------|------------|:---:|:---:|:---:|
| **公有化用户** | `/home/yhz/{username}/` | ❌ 数据在公司侧 | ✅ | ✅ |
| **私有化用户** | `{ceph_endpoint}/`（工厂 Ceph） | ✅ 本地 | ✅ | ✅ |
| **管理员** | `{ceph_endpoint}/` → `/home/yhz/admin/` | ✅ 本地 | N/A | ✅ 看所有人 |

> **核心理解**：
> - `in_data/` 是公司侧统一存储，**只有管理员能直接访问**
> - 公有化用户的数据一开始就在 `in_data/` 中，只能通过前端看到
> - 私有化用户的数据在工厂本地（`ceph_endpoint`），可本地文件系统 + 前端同时看到
> - 管理员就是"部署在公司里的私有化用户"，数据两头都有


## 四、数据库模型改动

### 4.1 IotUser 模型

```python
class IotUser(BASE):
    __tablename__ = "iot_users"
    id = Column(Integer, primary_key=True, autoincrement=True)
    username = Column(String(128), unique=True, index=True, nullable=False)
    password_hash = Column(String(256), nullable=False)
    is_admin = Column(Integer, default=0)
    deployment_mode = Column(String(32), default="public")   # "public" / "private"
    ceph_endpoint = Column(String(512), default="")           # 私有化用户的 Ceph 路径
    created_at = Column(DateTime, default=datetime.utcnow)
```

### 4.2 字段说明

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `deployment_mode` | VARCHAR(32) | `"public"` | `"public"` = 公有化，`"private"` = 私有化 |
| `ceph_endpoint` | VARCHAR(512) | `""` | 私有化用户的 Ceph 挂载路径；公有化用户为空 |

### 4.3 注册时自动创建目录（v4 新增）

**每个用户注册时，后端自动创建 `nifi-data/` 和 `real_nifi_data/` 目录**，无需管理员手动执行脚本。

注册流程：
```
用户注册 → auth.py register()
  → 写入 iot_users 表
  → 调用 _resolve_user_storage_root(username) 自动创建目录
  → 返回注册成功
```

`_resolve_user_storage_root` 函数内部逻辑：
```python
def _resolve_user_storage_root(username: str) -> Path:
    """根据用户部署模式返回存储根路径，自动创建子目录。
    
    公有化: /home/yhz/{username}/
    私有化: {ceph_endpoint}/
    """
    session = SessionLocal()
    try:
        user = session.query(IotUser).filter(IotUser.username == username).first()
        if user and user.deployment_mode == "private" and user.ceph_endpoint:
            root = Path(user.ceph_endpoint)
        else:
            root = IN_DATA_BASE_DIR / username
        # 自动创建 nifi-data 和 real_nifi_data 子目录
        (root / "nifi-data").mkdir(parents=True, exist_ok=True)
        (root / "real_nifi_data").mkdir(parents=True, exist_ok=True)
        return root
    finally:
        session.close()
```

## 六、核心路径解析函数（v4 统一入口）

### 6.1 新增统一路径代理函数

```python
def _get_user_nifi_dir(username: str, sub: str = "") -> Path:
    """返回用户 nifi-data 下的指定子目录，自动创建。"""
    root = _resolve_user_storage_root(username) / "nifi-data"
    if sub:
        root = root / sub
    root.mkdir(parents=True, exist_ok=True)
    return root

def _get_user_real_nifi_dir(username: str, sub: str = "") -> Path:
    """返回用户 real_nifi_data 下的指定子目录，自动创建。"""
    root = _resolve_user_storage_root(username) / "real_nifi_data"
    if sub:
        root = root / sub
    root.mkdir(parents=True, exist_ok=True)
    return root
```

### 6.2 全局常量保留作 fallback

| 常量 | 保留方式 |
|------|---------|
| `NIFI_BASE_DIR` | 保留为默认值，标记 `# deprecated` |
| `NIFI_REAL_BASE_DIR` | 保留为默认值，标记 `# deprecated` |
| `IN_DATA_BASE_DIR` | 保留（根目录不变，子目录按用户） |
| `NIFI_OUTPUT_DIR` 等 16 个常量 | 保留但不再直接使用，所有调用改为通过 `_get_user_nifi_dir()` |

## 八、NiFi 容器策略（v4 新增）

### 8.1 本地模拟：方案 A — 共享容器 + 后端搬文件

```
┌─────────────────────────────────────────┐
│  共享 NiFi 容器 (iot-nifi)               │
│  ┌─────────────────────────────────┐    │
│  │ Docker volume:                   │    │
│  │   /home/yhz/real_nifi_data  ←    │    │
│  │   /opt/nifi/.../data/iot         │    │
│  └─────────────────────────────────┘    │
│          │                              │
│          ▼ 产出文件                      │
│  /home/yhz/real_nifi_data/export_jobs/  │
│          │                              │
│          ▼ 后端识别 username 后搬文件    │
│  /home/yhz/{username}/real_nifi_data/   │
│  /home/yhz/{username}/real_nifi_data/ │
└─────────────────────────────────────────┘
```

**流程**：
1. NiFi 容器启动，挂载全局 `/home/yhz/real_nifi_data/` 作为工作区
2. 导出任务执行完毕，产物写入全局工作区
3. 后端扫描完成的任务，根据 `username` 把文件搬到用户自己的目录
4. 用户看到的文件树指向自己的目录

**优点**：无需多容器，资源消耗低，适合本地模拟
**缺点**：全局工作区是临时中转站，文件需要搬移

### 8.2 生产环境：方案 B — 每用户独立 NiFi 容器

```
┌──────────────────────────────────────────┐
│  zhangsan (公有化)                        │
│  Docker: iot-nifi-zhangsan               │
│  volume: /home/yhz/zhangsan/real_nifi_data/ │
├──────────────────────────────────────────┤
│  wangwu (私有化)                          │
│  Docker: iot-nifi-wangwu                 │
│  volume: /home/yhz/wangwu/real_nifi_data/ │
└──────────────────────────────────────────┘
```

每用户独立容器，各自挂载自己的目录。端口动态分配，记录在数据库中。

## 十一、关键设计决策

| 决策点 | 结论 |
|--------|------|
| 用户标识 | 使用 `username`，废弃 `factory-001` |
| 每个用户目录结构 | 统一包含 `nifi-data/` 和 `real_nifi_data/` |
| 公有化存储路径 | `/home/yhz/{username}/` |
| 私有化存储路径 | `{ceph_endpoint}/`（直接包含子目录，不加 username） |
| 注册时自动创建目录 | ✅ v4 新增 |
| NiFi 容器（本地模拟） | 共享容器 + 后端搬文件 |
| NiFi 容器（生产） | 每用户独立容器 |
| 管理员拉取方式 | 手动触发（内部管理页按钮） |
| factory_id → username | 逐步迁移，保留旧列做 fallback |

## 十二、真实部署迁移指南（v4 新增，详细版）

### 12.1 当前状态

本地模拟阶段，所有数据在 `/home/yhz/` 下：

```
/home/yhz/
├── admin/{nifi-data,real_nifi_data}/       ← 管理员
├── wangwu/{nifi-data,real_nifi_data}/      ← 私有化（模拟工厂 Ceph）
├── in_data/{zhangsan,lisi,admin}/          ← 公司侧存储
```

### 12.2 迁移目标

生产环境，公司 Ceph 和工厂 Ceph 分别挂载：

```
/mnt/company-ceph/                          ← 公司 CephFS 挂载点
└── /home/yhz/{username}/{nifi-data,real_nifi_data}/

/mnt/factory-ceph-{username}/               ← 各工厂 CephFS 挂载点
└── {nifi-data,real_nifi_data}/
```

### 12.3 迁移步骤

#### 步骤 1：安装 Ceph 客户端

```bash
# Ubuntu
sudo apt install -y ceph-common ceph-fuse

# CentOS
sudo yum install -y ceph-common ceph-fuse
```

#### 步骤 2：获取 Ceph 配置和密钥

从公司运维获取：
- Ceph Monitor 地址（如 `10.0.1.100:6789`）
- Ceph 用户名（如 `admin`）
- Ceph 密钥环文件（`ceph.client.admin.keyring`）

#### 步骤 3：挂载公司 Ceph

```bash
# 创建挂载点
sudo mkdir -p /mnt/company-ceph

# 挂载 CephFS
sudo ceph-fuse -m 10.0.1.100:6789 /mnt/company-ceph \
  --id admin \
  --keyring /etc/ceph/ceph.client.admin.keyring

# 验证
ls /mnt/company-ceph/
df -h /mnt/company-ceph/

# 开机自动挂载（/etc/fstab）
# 10.0.1.100:6789:/ /mnt/company-ceph ceph name=admin,keyring=/etc/ceph/ceph.client.admin.keyring,_netdev,noatime 0 0
```

#### 步骤 4：迁移本地数据到公司 Ceph

```bash
# 确保目标目录存在
sudo mkdir -p /mnt/company-ceph/in_data

# 迁移数据
sudo rsync -avz --progress /home/yhz/ /mnt/company-ceph/in_data/

# 迁移完成后创建符号链接（保持代码兼容）
sudo ln -s /mnt/company-ceph/in_data /home/yhz
```

#### 步骤 5：更新用户 ceph_endpoint

管理员脚本更新数据库中的 `ceph_endpoint`：

```bash
# 管理员
sqlite3 /home/yhz/iot/v1-backend/data/app.db \
  "UPDATE iot_users SET ceph_endpoint='/mnt/company-ceph/admin' WHERE username='admin';"

# 私有化用户（需要先挂载工厂 Ceph）
sqlite3 /home/yhz/iot/v1-backend/data/app.db \
  "UPDATE iot_users SET ceph_endpoint='/mnt/factory-ceph-wangwu' WHERE username='wangwu';"
```

#### 步骤 6：验证

```bash
# 1. 重启服务
sudo systemctl restart iot-backend.service

# 2. 验证管理员登录
curl -X POST http://localhost:8081/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' -c /tmp/cookies.txt

# 3. 验证文件树
curl -b /tmp/cookies.txt http://localhost:8081/api/v1/internal/users

# 4. 验证拉取
curl -X POST http://localhost:8081/api/v1/internal/private-users/wangwu/pull \
  -b /tmp/cookies.txt \
  -H "Content-Type: application/json" \
  -d '{"source_paths":["/mnt/factory-ceph-wangwu/nifi-data"]}'
```

### 12.4 工厂 Ceph 连通性方案

私有化工厂的 Ceph 通常部署在内网，公司服务器无法直接访问。三种方案：

#### 方案 1：反向 SSH 隧道（推荐）

```
工厂侧主动建立隧道，公司侧通过隧道访问工厂 Ceph
```

```bash
# 工厂机器执行（需配置 autossh 自动重连）
autossh -M 0 -fN \
  -R 0.0.0.0:22001:127.0.0.1:6789 \
  root@公司服务器IP

# 公司服务器挂载
sudo ceph-fuse -m 127.0.0.1:22001 /mnt/factory-ceph-wangwu \
  --id admin --keyring /etc/ceph/ceph.client.admin.keyring
```

**优点**：工厂防火墙无需开放端口，SSH 加密
**缺点**：工厂需保持一台机器在线

#### 方案 2：工厂主动推送

```
工厂侧定时任务 → 推送数据到公司 S3/OSS → 公司侧拉取
```

```bash
# 工厂侧 cron（每小时）
0 * * * * s3cmd sync /home/yhz/wangwu/nifi-data/ s3://iot-data/wangwu/nifi-data/

# 公司侧 cron（每 30 分钟）
*/30 * * * * s3cmd sync s3://iot-data/wangwu/ /mnt/company-ceph//home/yhz/wangwu/
```

**优点**：工厂完全控制推送时机，无需公司侧入站连接
**缺点**：数据延迟较大

#### 方案 3：VPN 专线

```
工厂与公司之间建立 VPN 隧道，Ceph 流量走加密通道
```

```bash
# WireGuard 示例
# 工厂侧 /etc/wireguard/wg0.conf
[Interface]
PrivateKey = ...
Address = 10.200.0.2/24

[Peer]
PublicKey = ...
Endpoint = 公司服务器IP:51820
AllowedIPs = 10.200.0.0/24
```

**优点**：最稳定，延迟最低
**缺点**：需要双方 IT 配合，配置复杂

## 十三、验收标准

1. 注册公有化用户 → 目录自动创建 → 导出产物落在 `/home/yhz/{username}/nifi-data/`
2. 注册私有化用户 → 目录自动创建 → 导出产物落在 `{ceph_endpoint}/nifi-data/`

4. 管理员切换用户后文件树正确刷新
5. 选中私有化用户时显示"拉取"按钮并可拉取数据
6. 普通用户文件中心看到自己的 `nifi-data` + `real_nifi_data` 双树
7. 普通用户看不到内部管理页
8. 非管理员无法访问 `/api/v1/internal/*` 接口
9. 所有 `factory_id` 引用已替换为 `username`

## 十四、风险与应对

| 风险 | 应对 |
|------|------|
| 私有化 Ceph 未挂载或不可达 | 拉取前检查路径是否存在，返回明确错误 |
| 用户名与历史 factory-001 不兼容 | 保留 `factory_id` 列做 fallback，逐步迁移 |
| 大文件拉取超时 | 改为异步任务，返回任务 ID 供轮询 |
| 并发拉取 IO 过高 | 限制同时拉取数量，加入队列 |
| 工厂 Ceph 网络不通 | 优先用反向 SSH 隧道或工厂主动推送 |
| NiFi 多容器资源消耗 | 共享容器 + 后端搬文件（本地模拟），闲置容器自动停止 |
| 下拉菜单用户过多 | 支持搜索过滤 |
