# V4 公有化与私有化部署总方案

**版本：v4.0 | 日期：2026-06-16**
**基于：**《AI模块综合执行方案（融合NiFi、联邦学习与双模部署）》

---

## 一、需求定义

### 1.1 公有化部署
工厂把通过我们网站规整好的训练数据，直接存放到**我们的 Ceph** 里。数据在我们自己的机器上，可以直接用于中心训练。

### 1.2 私有化部署
工厂把通过我们网站规整好的训练数据，存放在**工厂自己的 Ceph** 里。管理员通过内部管理页面切换用户并拉取数据到我们机器，再用于中心训练。

### 1.3 用户与工厂关系
每个用户就是一个工厂，用户名即工厂标识。一个工厂的 Ceph 上只有该工厂自己的数据。

### 1.4 各角色数据访问权限

| 角色 | 数据物理位置 | 本地文件系统 | 前端文件中心 | 管理员内部页 |
|------|------------|:---:|:---:|:---:|
| 公有化用户 | `/home/yhz/{username}/` | ❌ 公司侧 | ✅ | ✅ |
| 私有化用户 | `{ceph_endpoint}/` | ✅ 本地 | ✅ | ✅ |
| 管理员 | `/home/yhz/admin/` | ✅ 本地 | N/A | ✅ 看所有人 |

## 二、核心数据流

```
工厂用户登录 → 配置数据库连接 → 创建导出任务
    → NiFi / Local 执行器处理 → 产出文件
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
【公有化用户】【私有化用户】【管理员（公司侧私有化用户）】
    │         │         │
 公司本地    工厂 Ceph  公司本地
 /home/yhz/  {ceph_endpoint}/
 {username}/ ├── nifi-data/
 └── real     └── real_nifi
      _nifi        │
            管理员拉取到 /home/yhz/{user}/
```

---

## 三、数据目录结构

每个用户统一目录：
```
{storage_root}/
├── nifi-data/          ← Local 执行器产物
│   ├── output_csv/  output_json/  output_tsv/
│   ├── inbox_csv/   inbox_json/   inbox_tsv/
│   ├── csv_to_json/ json_to_csv/  tsv_to_json/
│   ├── json_to_tsv/ csv_to_tsv/   tsv_to_csv/
│   ├── tagged_output/  silent_exports/  exports/  export_jobs/
└── real_nifi_data/     ← NiFi 执行器产物
    └── output_csv/  output_json/  output_tsv/  export_jobs/
```

## 四、关键设计决策

| 决策点 | 结论 |
|--------|------|
| 用户标识 | 使用 `username`，废弃 `factory-001` |
| 公有化存储路径 | `/home/yhz/{username}/` |
| 私有化存储路径 | `{ceph_endpoint}/` |
| 注册时自动创建目录 | ✅ v4 新增 |
| NiFi 容器（本地模拟） | 共享容器 + 后端搬文件 |
| NiFi 容器（生产） | 每用户独立容器 |
| 管理员拉取方式 | 手动触发 |

## 六、验收标准

1. 注册公有化用户 → 目录自动创建 → 导出产物落在 `/home/yhz/{username}/nifi-data/`
2. 注册私有化用户 → 目录自动创建 → 导出产物落在 `{ceph_endpoint}/nifi-data/`
3. 管理员下拉菜单列出所有用户（标注部署模式）
4. 管理员切换用户后文件树正确刷新
5. 选中私有化用户时显示"拉取"按钮并可拉取数据
6. 普通用户文件中心看到自己的 `nifi-data` + `real_nifi_data` 双树
7. 普通用户看不到内部管理页
8. 所有 `factory_id` 引用已替换为 `username`
