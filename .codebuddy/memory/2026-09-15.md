### 幂等性核对（deploy.sh / setup.sh / check_env.sh 实读）
- **第 0 步 `check_env.sh --quiet` 是纯检测**（只读，可反复跑）。`check_port()` 把
  `serve.py|uvicorn|mysqld|mariadbd|nginx|python|docker-proxy` 归为「自用→部署时自动重启」，
  **不算阻塞** → 重跑时服务正在跑也不会被闸门拦下（这是幂等的前提）。
- **`config.env` 与 `.deploy-secrets` 都不在离线包内**（已核对 tgz 的 deploy-kit 顶层清单，只有
  `config.env.example`）→ 重跑解压**不会覆盖**目标机这两份文件 → 密码/密钥保持稳定。
- `.deploy-secrets` 存在则**复用**（deploy.sh L99-101），不重新生成 → DB_PASS/SECRET_KEY/META_KEY 不变。
- `v1-backend/data/app.db` 被排除在包外；tar 解压只覆盖不清空 → SQLite 账号库保留。
- 系统软件：`install_sysdeps.sh` 情形①「齐全 → 直接跳过」（L126）。
- 数据库：`init.sql` 全 `IF NOT EXISTS` → 数据保留；仅 `${DB_USER}@localhost` 密码被重置为 config.env 里的 DB_PASS（有告警）。
- NiFi：`docker load`（同 tag 重复加载无害）+ `compose up -d` + `docker update --restart`，
  **4 个 worker 每次都 `docker cp`**（且先 `mkdir -p real_nifi_data/bin`）→ 每次都会补齐。
- ODBC：`install_odbc.sh` 开头「已装就跳过」（`odbcinst -q -d | grep -i "SQL Server"`），否则按
  `$DISTRO_KEY` 选专属闭包重装；**每次 deploy 都会调用**。
- Nginx / 防火墙 / systemd：重写配置 + reload / `ufw allow`（幂等）。
- ⚠️ **唯一会「变」的**：`userctl.py create` 对已存在用户走 `UPDATE`（重置密码 hash）。
  因 `setup.sh` 会沿用旧 `config.env` 的 `SITE_PASS`（L114-121、L179），所以**密码不变**；
  只有手工改过 `config.env` 的 SITE_PASS 才会跟着变。另：重跑时若把「角色/账号名」答成别的，
  会**新建另一个账号**（旧的仍在）→ 建议答案与首次一致。

- 可以反复执行（先检测后执行、幂等），**但有两点例外**：账号密码会被重置为 config.env 的值（值本身不变）、
  重跑会重新 `docker load` 1.6G 镜像（耗时属正常）。
- 「上次残缺 → 完整版」：**能**。上次失败的两项（worker 未进容器、ODBC 装不上）在 deploy.sh 里
