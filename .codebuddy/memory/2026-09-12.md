## 第十轮：ODBC 依赖闭包修复 + 最终回归 35/35 + 最终包

### ODBC 根因的完整链条（第 3 个漏依赖后放弃手工列清单）
readline-common（缺失）→ libreadline8 没配 → unixodbc 没配 → msodbcsql17 没配 → ODBC 不可用
**教训：deb 依赖闭包不要手工列，用 apt 递归闭包一次抓全：**
    apt-get download $(apt-cache depends --recurse --no-recommends --no-suggests \
      --no-conflicts --no-breaks --no-replaces --no-enhances <包名列表> 2>/dev/null | grep "^\w" | sort -u)

## 第十二轮：卸载安全重构（清单驱动）——用户批评"别犯这种错，检查还有无类似"

### 审计发现的问题（uninstall_all.sh）
1. 🔴 `apt-get purge -y 'gcc*' 'cpp*'` —— apt 把含正则字符的参数当正则，
   `gcc*` 会匹配 libgcc-s1（glibc 依赖的系统基础库）→ **可能直接搞坏整台机器**。已改为精确包名。
2. 🔴 无法区分「我们装的」和「机器上原本就有的」→ 卸载会把机器原有的 mysql/docker/nginx 连数据一起删。
3. 🟠 默认删整个 /home/yhz（用户明确要求：只删 iot，保留 /home/yhz）。

### 重构方案（清单驱动）
- install_sysdeps.sh：/var/lib/iot-platform/ 记录 pkg-before.list（装前已装包）、
  pre-existing.txt（mysql/docker/nginx 是否原本就存在）、pkg-after.list、pkg-new.list（本次新装）
- deploy.sh：firewall-ports.txt 记录实际放行的端口
- uninstall_all.sh：按清单判断——清单说是我们装的才卸；机器上原有的保留并提示；
  没有清单（老版本装的）→ 只卸平台专属（iot 服务/NiFi/msodbcsql17//home/yhz/iot），通用软件保留
- 所有 purge 改为精确包名（purge_exact 函数，先 dpkg -s 确认装了才 purge）
- /home/yhz 默认保留，只删平台目录（iot、4 个数据根、SITE_USER 数据根）；--purge-home 才删整个家目录

### 状态
- 全部脚本 bash -n 通过；危险正则已清零
- ⚠️ 新的清单驱动卸载逻辑【尚未在容器里自动化验证】（用户停止了测试循环）
  建议下次部署前先跑一轮：安装 → 卸载 → 确认数据完好；特别是"机器上原本就有 MySQL"的场景
