## 🔑 跨 Windows 传输会丢可执行权限（真实踩坑）
用户在 Windows 打包 zip → 传到 Ubuntu22 → 解压后执行报：
```
sha256sum -c iot-install.run.sha256  → iot-install.run: 成功   (内容完好)
sudo ./iot-install.run               → sudo: ./iot-install.run: 找不到命令  ❌
```
**根因**：Windows 文件系统没有 Linux 可执行权限位，打包/传输/解压后 `+x` 丢失。
`sudo` 对不可执行文件报的是"找不到命令"（信息有误导性）。
**解决**：`chmod +x iot-install.run` 后再执行（或 `sudo bash iot-install.run`）。
**判别口诀**：
- `sha256sum -c` **失败** → 内容损坏，必须重传
- `sha256sum -c` **成功**但执行报"找不到命令" → 只是缺 +x 权限，chmod 即可
→ 已把 `chmod +x` 补进 `交付操作卡.txt`（第4步）和 `交付说明.txt`（第2步，含上面这个判别口诀）

## 🚨 复盘第一次真实部署失败：根因是「系统软件在线安装」
目标机 202.113.76.54（Ubuntu 22.04）**只放行 HTTPS(443)，HTTP(80) 被墙** →
`apt` 连 `http://security.ubuntu.com:80` 全部超时 → 部署卡死在「装基础软件」。
之前的原则是「Python 依赖/NiFi 镜像离线，系统软件靠 apt」，这一步就把部署卡住了。

### 解决办法（两层保险，本次都做了）
1. **自动把 apt 源 http:// 换成 https://**（治本轮故障）
   - 新增 `deploy-kit/install_sysdeps.sh`：①软件齐全→跳过 ②有离线 deb→dpkg 离线装
     ③都没有→apt 失败后自动把 `/etc/apt/sources.list(.d/*)` 的 `http://` 改成 `https://` 重试
     （原文件备份 `*.bak.iot`），装完自动 `systemctl enable --now mysql docker`
   - `deploy.sh` 第 1 步改为调用它，替换原来那段硬编码 apt
2. **把系统软件也离线化**（治「完全断网」场景）
   - 新增 `deploy-kit/prepare_sysdeps.sh` + `tools/container_fetch_debs.sh`
   - 产物 `offline-assets/deb/sysdeps/ubuntu-{20.04,22.04,24.04}/`，共 **419M**
     （20.04 135 个 / 22.04 108 个 / 24.04 83 个 deb），打包时默认打进包

### 关键实现细节 / 踩坑
- **容器里 HTTPS 证书校验失败**：本机网络有 TLS 代理，`ubuntu:22.04` 容器不信任其证书链
  → `docker run -v /etc/ssl/certs/ca-certificates.crt:/etc/ssl/certs/ca-certificates.crt:ro` 解决
  （同时容器内脚本还会轮询 阿里云/清华/中科大/华为/官方 多个源，最后才降级关证书校验）
- **`LC_ALL` 排序坑**：`for f in *.deb` 在 en_US 下会忽略 `-`/`_`，
  把 `perl` 排到 `perl-base` 前面 → perl 配置失败 → 连累 `mysql-server` 未配置。
  改为**一次性 `dpkg -i` 全部 deb**（由 dpkg 自己做拓扑排序）+ 多轮 `dpkg --configure -a`，
  并 `export LC_ALL=C`。**已在断网容器（--network none）实测：108 个包全部配置成功**
- **防降级**：逐包 `dpkg --compare-versions`，机器上已有同等/更新版本就跳过不覆盖
- **架构校验**：`sysdeps/<发行版>/ARCH` 与 `dpkg --print-architecture` 不一致就不用离线包
- **`--force-confold`**：避免 dpkg 交互式询问配置文件冲突

### ⚠️ 本执行环境的一个坑（会影响脚本调试）
在这个 CodeBuddy 执行环境里，**`ls` 把 stdout 重定向到文件时返回 255**（管道方式如
`ls | wc -l` 正常）。`make_offline_package.sh` 有 `set -e`，因此 `X="$(ls dir)"` 会
**静默退出（exit 255，无任何报错）** —— 排查了很久。
→ 已把该处改成 glob 展开：`X="$(printf '%s ' dir/*/)"`。
