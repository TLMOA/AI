### xattr 方案落实情况
- **xattr 真实可用**：文件确实有 user.meta（AES-256-GCM 加密）+ user.checksum（SHA-256）
- **双写策略**：xattr + .meta.json 同时写入（非纯零文件方案）
- **内部管理页 xattr 检查区域**：调用后端 API `/files/{id}/xattr`，后端优先从 xattr 解密读取，回退 .meta.json
- **当前问题**：后端进程未设置 META_XATTR_KEY → _using_xattr=False → xattrEnabled 显示 False（但文件确实有 xattr）
- **schema 不一致**：meta.schema.json 定义 additionalProperties:false，但实际写入更多字段
- **storagePath 泄露**：xattr API 直接返回含 storagePath 的原始 meta，未脱敏
