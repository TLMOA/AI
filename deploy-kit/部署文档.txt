【读者对象】执行部署的技术人员
【适用系统】Ubuntu 22.04 / 24.04（x86_64）—— 离线完整支持，推荐
            其他 Ubuntu / Debian 也可，但系统软件需能连 apt 源（脚本会自动切 HTTPS）
            ⚠️ 本平台要求 Python ≥3.9：Ubuntu 22.04 自带 3.10、24.04 自带 3.12，都满足；
               Ubuntu 20.04 自带 3.8，**不能直接部署**，需先自行安装 Python 3.10+
【预计耗时】15~40 分钟（绝大部分时间机器自动执行）

【需要传的 3 个文件】
    iot-install.run           1.7G    安装程序
    iot-install.run.sha256    82B     校验文件（务必带上）
    部署文档.txt                      本文件

    （就这 3 个。其他脚本都在 iot-install.run 里面，解压后自动出现在
      /home/yhz/iot/deploy-kit/，包括卸载脚本，都不需要单独传。）

【部署前先做一件事】不用做。
    安装脚本会自动检测本机防火墙（ufw/firewalld）并放行自己的端口；
    只有「云主机安全组」需要在控制台手工放行 5174（这不是脚本权限能碰的）。
    部署前也可以先跑一次自检，它会自动判断这台机器能不能装、缺什么：
        sudo ./check_env.sh

########################################################
#
#   第一部分  极简部署步骤（一句话版）
#
#     chmod +x iot-install.run  →  sudo ./iot-install.run  →  一路回车
#
########################################################

前提：iot-install.run 已复制到服务器硬盘上（建议放 /root，不要放 U 盘里直接跑）。

--------------------------------------------------------
第 1 步   进入文件所在目录
--------------------------------------------------------

    cd /root
（换成你实际存放的目录）

--------------------------------------------------------
第 2 步   加执行权限
--------------------------------------------------------

    chmod +x iot-install.run
（从 Windows 传过来的文件必须做这一步，否则报"找不到命令"）

--------------------------------------------------------
第 3 步   执行安装
--------------------------------------------------------

    sudo ./iot-install.run

--------------------------------------------------------
第 4 步   回答 4 个问题（大多直接回车）
--------------------------------------------------------

    【1/4】这台机器给谁用？
            → 输入 1 或 2
              1 = 忽米（管理员）
              2 = 工厂（普通用户）

    【2/4】登录账号名叫什么？
            → 直接回车（忽米默认 humi，工厂默认 factory01）

    【3/4】可以进内部管理页吗？
            → 直接回车

    【4/4】访问地址（已自动检测）
            → 直接回车

    如果服务器上已有 MySQL 且 root 设了密码，会多问一次 root 密码；
    没有则不会问（默认免密）。

    最后问"现在开始部署吗？"
            → 直接回车

然后等待 15~40 分钟，全自动。

--------------------------------------------------------
完成
--------------------------------------------------------

屏幕会显示账号密码，例如：

    =========== 部署完成 ===========
      前端      http://192.168.1.50:5174
      本站账号  humi
      本站密码  Ab3xK9mP2q
    ================================

【记下账号密码！】忘了可以看：
    cat /home/yhz/iot/deploy-kit/.deploy-secrets

用浏览器打开：   http://服务器IP:5174
（把服务器IP 换成实际的）

--------------------------------------------------------
出错了怎么办（速查）
--------------------------------------------------------

· 提示"找不到命令"     → 执行第 2 步 chmod +x
· 提示权限不足         → 命令前加 sudo
· 卡在装软件/apt 报错  → 安装程序会优先用包内离线 deb（零下载）；
                          没有对应发行版的包时，自动把软件源 http 换成 https 重试；
                          仍失败则让 IT 预装基础软件（mysql/docker/nginx）后重跑
· 中途断了             → 重新执行 sudo ./iot-install.run（可重复执行）
· 忘了密码             → cat /home/yhz/iot/deploy-kit/.deploy-secrets
· 浏览器打不开         → 本机防火墙已自动放行；云主机请到控制台放行 5174，
                          然后跑 sudo ./verify.sh

详细原因见第五部分。


########################################################
#
#   第二部分  传文件与校验
#
########################################################

--------------------------------------------------------
【第 1 步】在 Windows 上先校验（确认传输没坏）
--------------------------------------------------------

  正确值就写在 iot-install.run.sha256 这个文件里（用记事本打开即可看到
  一串 64 位字符，后面跟着文件名）。

  在文件所在目录打开 CMD，执行：

      certutil -hashfile iot-install.run SHA256

  把输出的那串字符与 .sha256 文件里的**逐位对比**，完全一致才算完好。
  一致 → 继续；不一致 → 重新传输，不要将就使用。

  提示：文件大小约 1.7G（1,74x,xxx,xxx 字节量级），明显偏小说明没传完。

--------------------------------------------------------
【第 2 步】传到目标服务器
--------------------------------------------------------

  用 U 盘或内网传输，把 3 个文件放到服务器上（建议 /root）：

      /root/iot-install.run
      /root/iot-install.run.sha256
      /root/部署文档.txt

  【注意】不要放在 U 盘里直接运行（解压慢），先复制到服务器硬盘。

--------------------------------------------------------
【第 3 步】服务器上再次校验
--------------------------------------------------------

      cd /root
      sha256sum -c iot-install.run.sha256

  输出 "iot-install.run: 成功" → 继续。

  【重要判别口诀】
      sha256sum -c 失败                 → 文件内容损坏，必须重新传输
      sha256sum -c 成功但执行报"找不到命令" → 只是缺可执行权限，chmod +x 即可

--------------------------------------------------------
【第 4 步】执行安装
--------------------------------------------------------

      chmod +x iot-install.run
      sudo ./iot-install.run

  （文件不在当前目录就换成实际路径；忘了位置用：
    find / -name "iot-install.run" 2>/dev/null）

--------------------------------------------------------
【1】部署架构速览（装完有什么）
--------------------------------------------------------

  组件            端口      说明
  ------------    ------    --------------------------------
  前端(serve.py)  5174      网页入口，含 /api/v1 反向代理（绑 0.0.0.0，可远程访问）
  后端(FastAPI)   8081      业务接口（仅监听 127.0.0.1，只经前端代理暴露）
  NiFi(容器)      8080      FlowFile 异步处理（iot-nifi）
  MySQL           3306      用户认证库（nifi 库）
  Nginx           80        可选入口，代理到 5174（装不上也不影响使用）

  容器：iot-nifi（镜像 iot-nifi-python:latest，约 1.6G）

  ⚠️ 访问方式：浏览器打开 http://<服务器IP>:5174 即可。
     Nginx 的 80 端口只是「顺带」的入口 —— 很多内网/防火墙会挡 80，
     所以不要依赖 80，前端 5174 才是始终可用的入口。

  ⚠️ NiFi 界面必须用 https://localhost:8080/nifi 访问
     （用服务器 IP 会报 Invalid SNI，这是 NiFi 的 TLS 校验行为，不是故障）。

--------------------------------------------------------
【2】关键路径
--------------------------------------------------------

  /home/yhz/iot/                              项目代码
  /home/yhz/iot/deploy-kit/                   部署工具包
  /home/yhz/iot/deploy-kit/config.env         本机部署参数
  /home/yhz/iot/deploy-kit/.deploy-secrets    自动生成的密码密钥（权限 600）
  /home/yhz/{账号名}/                         用户数据目录（4 个数据根）
  /etc/systemd/system/iot-backend.service     后端服务
  /etc/systemd/system/iot-frontend.service    前端服务

  用户数据目录结构（每个账号一套）：

  /home/yhz/{账号名}/
  ├── nifi-data/              Local 模式数据
  ├── real_nifi_data/         NiFi 模式数据
  ├── tagged_nifi_data/       Local 模式打标结果
  └── tagged_real_nifi_data/  NiFi 模式打标结果

--------------------------------------------------------
【3】部署模式说明
--------------------------------------------------------

  · 每台机器部署一套，只创建一个账号（忽米用管理员，工厂用普通账号）
  · Local 模式：后端直接处理，不依赖 NiFi
  · NiFi 模式：交给容器异步处理，失败会自动回退本地

--------------------------------------------------------
【4】部署前检查（强烈建议先做）
--------------------------------------------------------

【硬件要求】
  最低：8 核 CPU / 16G 内存 / 100G 硬盘（/home 剩余 ≥ 20G）
  说明：NiFi 镜像 1.6G 且运行吃内存，内存不足会被系统杀掉。
        另外 /var/lib/docker 所在分区建议 ≥ 10G（镜像在这里膨胀）。

【软件要求】
  python3（含 venv，**版本 ≥3.9**）/ mysql / docker（含 compose）/ nginx。

  · 服务器能联网 → 不用管，安装时自动装
  · 服务器断网   → 包内备有 Ubuntu 20.04/22.04/24.04 的离线 deb，
                   会直接 dpkg 安装，不需要联网
  · 两者都不行   → 先手工装好：
        sudo apt install -y python3 python3-venv nginx mysql-server docker.io
        sudo apt install -y docker-compose-v2 || sudo apt install -y docker-compose

  ⚠️ Python 版本（最容易踩的一点）
     包内离线 wheel 覆盖 Python 3.10 / 3.11 / 3.12 / 3.13。
     安装脚本会自动从这几个版本里挑一个可用的解释器；四个都没有时才退回系统
     python3，并尝试联网装依赖。
       · Ubuntu 22.04 自带 python3.10 → 满足
       · Ubuntu 24.04 自带 python3.12 → 满足
       · Ubuntu 20.04 自带 python3.8  → **不满足**（应用依赖 pydantic 2.11，
         它硬性要求 Python ≥3.9）。这种机器请先装 3.10~3.13，或改用 22.04/24.04。

【环境体检】
  【不用人来判断】—— setup.sh 和 deploy.sh 都会**自动**先跑体检，
  通不过就直接停下来并打印原因（✗ 项），不会装到一半才失败。

  想自己看完整报告也可以：

      cd /home/yhz/iot/deploy-kit && sudo ./check_env.sh

  它自动检查并判定：
      1) 系统资源（CPU 架构 / 内存 / 磁盘 /home 与 docker 分区）
      2) 依赖软件是否齐全、离线 deb 是否覆盖本发行版（缺了会自动装，不算阻塞）
      3) 端口占用（5174/8081/8080/3306）—— 自动区分「本平台自己的进程（可重启）」
         和「别的程序（冲突）」，后者才判为不能装
      4) 版本匹配（Python 版本、CPU 架构）
      5) 现有环境冲突（已有 NiFi 容器 / 已有数据库的处理方式）

  最后输出「自动判定：可以部署」或「不能部署」并给出 ✗ 原因清单。

【5】向导 4 个问题的含义
--------------------------------------------------------

  ┌────────────────────────────────────────────────┐
  │【1/4】这台机器是给谁用的？                       │
  │   1) 忽米（平台方，管理员）                     │
  │   2) 工厂（客户，普通用户）                     │

  └────────────────────────────────────────────────┘
    → 决定账号权限。忽米选 1，工厂选 2。
      两者装出的软件完全相同，只是账号标志位不同。

  ┌────────────────────────────────────────────────┐
  │【2/4】这台机器上的登录账号名叫什么？             │
  │账号名 [默认 humi]:                              │
  └────────────────────────────────────────────────┘
    → 回车用默认值；或输入指定名称（会自动过滤空格和斜杠）。

  ┌────────────────────────────────────────────────┐
  │【3/4】这个账号可以进「内部管理页」吗？           │
  │可以进？[y/n，默认 y]:                           │
  └────────────────────────────────────────────────┘
    → 回车即可。选 y 则该账号可访问内部管理页；
      选 n 则仅普通用户权限（忽米将无法远程查看这台机器）。

  ┌────────────────────────────────────────────────┐
  │【4/4】访问地址已自动检测：192.168.x.x           │
  │地址 [回车 = 192.168.x.x]:                       │
  └────────────────────────────────────────────────┘
    → 回车即可。如需用域名访问，此处输入域名。

  之后还有一次确认：  现在开始部署吗？[y/n，默认 y]:  → 回车开始。

  【基础软件自动检测】向导会自动检查 python3/mysql/docker/nginx：
      缺 → 部署阶段自动安装（优先离线 deb）
      全 → 跳过，部署更快

--------------------------------------------------------
【6】安装程序背后做了什么
--------------------------------------------------------

  1) 创建运行用户 yhz（若已存在则跳过，不影响该用户）
  2) 解压到 /home/yhz，修正文件属主
  3) 启动配置向导，生成 config.env
  4) 打代码补丁：禁止自动创建默认 admin、关闭自助注册、下线注册页
  5) 建 Python 虚拟环境，从包内离线 wheel 安装依赖（零下载零编译）
  6) 初始化 MySQL（建库建用户）
  7) 安装 systemd 服务（开机自启）
  8) 加载 NiFi 镜像并启动容器（flows 已内置，自动运行）
  9) 创建本站唯一账号
  10) 配置 Nginx（可选）与 SQL Server ODBC 驱动（离线）

  若某步只告警未中断，部署结束时会集中列出「需要你关注的事项」。

  【输出说明 · 为什么看不到几百行刷屏了】
  安装第三方软件（dpkg/apt）本身会打印几百行原始输出，本程序已把它收进日志文件，
  屏幕上只保留「正在做什么 / 结果如何 / 失败了怎么办」：
      · 系统软件安装日志  /tmp/iot-sysdeps.log
      · SQL Server ODBC 日志  /tmp/iot-odbc-install.log
  某个环节失败时，脚本会自动把日志里最关键的几行回显出来；要看全部就打开上面两个文件。
  屏幕上的步骤编号形如 [deploy] 7/14 ... ，一路递增到 14/14（0 是环境体检）。

  【归属台账 · 什么算「我们装的」】
  部署时会在机器上留一份记录，目录 /var/lib/iot-platform/：
      pkg-new.list                  本平台装/管过的 apt 包
      files-rendered-by-iot.txt     本平台生成或覆盖过的文件（systemd / nginx / compose）
      dirs-created-by-iot.txt       本平台创建的目录
      services-enabled-by-iot.txt   本平台开启过的自启服务
      containers-by-iot.txt         本平台创建的容器
      users-created-by-iot.txt      本平台创建的账号
      pre-existing.txt              机器上原本就有的（mysql / docker / nginx）
      firewall-ports.txt            本平台放行过的端口
  它有两个用处：
      ① 重跑时判定归属：机器上某个残留（例如旧版本安装程序留下的 libodbc1）若台账里有记录
         → 是本平台装的 → 直接打破它、按当前这个安装包重建；
         台账里没有 → 那是别人的东西 → 只告警 + 给人工命令，绝不擅自删除。
      ② 卸载时只回收自己的，机器原本就有的绝不碰。
  查看： bash /home/yhz/iot/deploy-kit/tools/manifest.sh show

########################################################
#
#   第五部分  常见问题排查
#
########################################################

【1】sudo: command not found / 权限不足
    → 命令前必须加 sudo。

【2】No such file or directory
    → 路径错误。用 find / -name "iot-install.run" 2>/dev/null 找文件。

【3】卡在安装基础软件，报 apt 错误
    → 安装程序已内置三层自动处理，通常无需人工干预：
        ① 先查包内有没有「本发行版」的离线 deb → 有就直接装，零下载；
        ② 没有 → 走 apt；
        ③ apt 一旦失败 → 自动把软件源 http:// 换成 https:// 后重试
           （很多内网只放行 443，80 被挡会让 apt 连 security.ubuntu.com 全部超时）。
      自动切换成功时会打印：
            [sysdeps] 源已切换 HTTPS：/etc/apt/sources.list（原文件备份为 ...bak.iot）

    如果仍然失败，按下面排查：

    (a) 报 "连接超时 / 无法下载"（网络层）：
        · 看日志里有没有上面那句"源已切换 HTTPS"。有但仍不通 → 多半是 DNS 或代理问题。
        · 手工改用 HTTPS 源（Ubuntu 22.04 示例）：

            sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak
            sudo tee /etc/apt/sources.list > /dev/null <<'EOF'
            deb https://mirrors.aliyun.com/ubuntu/ jammy main restricted universe multiverse
            deb https://mirrors.aliyun.com/ubuntu/ jammy-updates main restricted universe multiverse
            deb https://mirrors.aliyun.com/ubuntu/ jammy-backports main restricted universe multiverse
            deb https://mirrors.aliyun.com/ubuntu/ jammy-security main restricted universe multiverse
            EOF
            sudo apt-get update

        · 若完全不通 → 问 IT 要内网 apt 镜像地址，或临时开通外网。

    (b) 已经完全断网的环境：
        · 最佳做法：让打包方先在能上网的机器执行
              cd /home/yhz/iot/deploy-kit
              ./prepare_sysdeps.sh 20.04 22.04 24.04
          把系统 deb 打进包里，目标机即可纯离线安装（dpkg，不联网）。
        · 来不及的话，请 IT 先手工装好，再重跑安装程序：
            sudo apt install -y python3 python3-venv nginx mysql-server docker.io
            sudo apt install -y docker-compose-v2 || sudo apt install -y docker-compose
        装完后重跑 ./iot-install.run —— 脚本会自动检测到"基础软件齐全"并跳过安装。

    (c) 报 "无法定位软件包 docker-compose-plugin"：
        Ubuntu 官方源里没有这个包名，它叫 docker-compose-v2 或 docker-compose。
        新版安装程序已自动依次尝试，无需处理；即便没装上，也只影响 NiFi 容器，可后补。

    【快速诊断】
            ping -c 2 8.8.8.8                                          # 有网吗
            curl -I --max-time 10 https://mirrors.aliyun.com/ubuntu/   # HTTPS 通吗
        能 ping 通、HTTPS 也通，但 apt 超时 → 就是 (a) 的 HTTP 被挡，换 HTTPS 源。

【4】浏览器打不开网站
    → 依次检查：
       1) 是否同一网络
       2) 本机防火墙脚本已自动放行；若是云主机，请在控制台「安全组」放行 5174
       3) cd /home/yhz/iot/deploy-kit && sudo ./verify.sh

【5】安装中断 / 服务器重启 / 上次没装完
    → 直接重跑 sudo /root/iot-install.run（脚本幂等，只补没做完的部分）
      重跑会自动做到「做过的事不再做」：
        · 不再问那 4 个问题（沿用上次答案，直接开跑）
        · 密码不重置（沿用已生成的密码）
        · NiFi 镜像已加载过就不再重复加载（省几分钟）
        · 已装的系统软件、已打的补丁、已建的账号都跳过
      想确认哪些没做完：看部署末尾的「以下事项需要你关注」列表。

【6】改密码 / 改配置（重跑不会动它们）
    改密码： cd /home/yhz/iot/deploy-kit && sudo bash set_password.sh
    改配置（账号名、端口、地址等）：
             cd /home/yhz/iot/deploy-kit && sudo bash setup.sh --reconfig
             （会重新问那 4 个问题；答完自动部署，数据不受影响）

【7】提示"用户总数不是 1"
    → 说明「禁用默认 admin」补丁没打上，实例多出了一个 admin 账号。
       自查： grep -c 'no-default-admin' /home/yhz/iot/v1-backend/app/db_models.py   # 应为 1
       修复： python3 /home/yhz/iot/deploy-kit/tools/patch_no_default_admin.py /home/yhz/iot
              然后 systemctl restart iot-backend

【8】NiFi 容器起不来 / 自动退出
    → 多为内存不足。检查 free -h，建议 ≥ 8G。
       查看日志：docker logs iot-nifi --tail 50

【9】连 SQL Server 报驱动错误
    → 执行 sudo ./install_odbc.sh 安装 ODBC 驱动（离线 deb 已在包内）。
       该脚本会自动按机器发行版挑对应的离线 deb，并自动处理一种历史遗留情况：
       早期版本在 22.04/24.04 上误装了 20.04 风格的 libodbc1（与 libodbc2 抢同一个 .so，
       症状是 dpkg 报"正试图覆盖 …libodbc.so.2.0.0"、unixodbc 一直"尚未配置"）。
       脚本检测到且版本与包内通用包一致时，会先自动移除它再重装；版本对不上则只告警不擅动。
       若仍失败（脚本末尾会打印手修命令 + 日志关键行）：
           sudo dpkg --purge --force-depends libodbc1
           cd /home/yhz/iot/deploy-kit && sudo bash install_odbc.sh
       验收： odbcinst -q -d      # 应列出 [ODBC Driver 17 for SQL Server]
       完整安装日志： /tmp/iot-odbc-install.log

【10】MySQL root 登录失败（部署卡在"初始化 MySQL"）
    → 这台机器的 MySQL root 设了密码。把密码填到
       /home/yhz/iot/deploy-kit/config.env 的 MYSQL_ROOT_PASS= 里，然后：
           cd /home/yhz/iot/deploy-kit && sudo ./deploy.sh
       （重跑不会影响已有数据）

【开机自启】以下组件均配置为开机自动启动 —— 服务器断电/重启后
无需人工干预，会自动全部恢复：

      · 后端   iot-backend.service    (systemd enabled)
      · 前端   iot-frontend.service   (systemd enabled)
      · NiFi   iot-nifi 容器          (restart: unless-stopped)
      · MySQL / Docker / Nginx        (systemd enabled)

  部署完成后建议核查一次：

      systemctl is-enabled iot-backend iot-frontend docker mysql nginx
      docker inspect iot-nifi --format '{{.HostConfig.RestartPolicy.Name}}'

  最后一条应输出 unless-stopped。
  若显示 no（多见于容器是早前用 docker run 手工创建的情况），
  执行下面命令修正，之后即可随机器自动启动：

      docker update --restart unless-stopped iot-nifi

【服务管理】
      systemctl status iot-backend iot-frontend
      systemctl restart iot-backend
      journalctl -u iot-backend -f            # 后端日志

【NiFi】
      docker ps | grep iot-nifi
      docker logs -f iot-nifi
      docker restart iot-nifi                 # 重启后 flow 自动恢复

  验证 NiFi 界面（本机）：用 https://localhost:8080/nifi/ 访问
  （用 IP 访问会报 Invalid SNI，属正常安全限制）

【端口】
      ss -lntp | grep -E "5174|8081|8080|3306"

【数据目录】
      ls /home/yhz/{账号名}/

【数据库】
      mysql -uroot -p nifi -e "select username,is_admin from iot_users"

【部署没成功 / 想改配置 —— 直接重跑，不要卸载】（首选，99% 的情况用这个）
      sudo /home/yhz/iot/deploy-kit/deploy.sh
      # 或整体重来：再跑一遍 sudo ./iot-install.run
    安装是幂等的：已完成的自定跳过，只补没完成的部分，已有数据不受影响。
    重跑不需要重新传任何文件——脚本就在机器上 /home/yhz/iot/deploy-kit/ 里。

    「做过的事就不再做」具体是：
      · 那 4 个问题  → 不再问（沿用 config.env，直接开跑）
      · 登录密码    → 不重置（已生成的密码继续用）
      · NiFi 镜像    → 已加载过就不再 load（1.6G，省几分钟）
      · 系统软件 / 补丁 / 账号 / 数据库表 → 都在就跳过（数据库表加 IF NOT EXISTS，数据保留）
      · 只有「上次没做完的」（如 worker 没进容器、ODBC 没装上）会被补上
    要改密码： cd /home/yhz/iot/deploy-kit && sudo bash set_password.sh
    要改配置： cd /home/yhz/iot/deploy-kit && sudo bash setup.sh --reconfig

【彻底卸载（把机器恢复原状）】
  ⚠️ 这是最后手段——只在「这台机器彻底不要装了」时才用。
     脚本随包提供，不用单独传输，解压后就在 /home/yhz/iot/deploy-kit/uninstall_all.sh

  ⚠️ 卸载会永久删除：本平台服务、MySQL 全部数据、Docker 全部镜像/容器、
     /home/yhz 下的平台目录（程序、数据根、账号密码文件）、ODBC 驱动、python venv 等。
     注意：默认保留 /home/yhz 家目录本身和运行用户（现场人员的登录环境不动）。
     如果机器上还跑着【别的东西】，不要在这台机器上执行。

     卸载按【归属台账】执行 —— 只回收本平台装过/改过的，别人的东西一律不碰：
       · 包   ：只卸台账 pkg-new.list 里登记的（gcc / python3-venv / ODBC 等）；
                机器原本就有的（mysql / docker / nginx）保留，并打印原因
       · 文件 ：只删「台账登记过 + 路径在白名单内」的（systemd unit / Nginx 站点 / odbcinst.ini）；
                不满足的会打印「保留」及原因
       · 服务/容器：只处理 iot- 开头的
       · 目录 ：平台目录整体删；台账里额外的目录**只删空的**，有数据的一律留着并提示
       · 防火墙：只回收本平台放行过的那几个端口（记录在 firewall-ports.txt）

      cd /home/yhz/iot/deploy-kit
      sudo bash uninstall_all.sh              # 会列出将删除的内容，输入 YES 确认
      sudo bash uninstall_all.sh --yes        # 免确认
      sudo bash uninstall_all.sh --keep-docker --keep-mysql   # 保留 Docker/MySQL 不卸

  · 默认【保留】运行用户 yhz —— 它往往是现场人员自己的登录账号，删了会把自己踢出去
    （确认要连用户一起删：sudo bash uninstall_all.sh --del-user）
  · 会同时回收部署时自动放行的防火墙端口、恢复被切换过的 apt 软件源、
    清理装包时自动创建的系统账号（mysql/docker）和 debconf 残留
  · 不管是「装成功的完整版」还是「装了一半的残留版」，都能卸干净；
    结束时会自动做残留自检，显示「已全部清除 ✓」或列出未清项
  · 卸载后重新部署：直接再跑一遍 sudo ./iot-install.run 即可（全新安装）

【重新打包 / 迁移到其他机器】
      cd /home/yhz/iot/deploy-kit
      ./make_offline_package.sh        # 生成离线包
      ./make_selfextract.sh            # 生成自解压安装器

  打包前建议先自测一次（在一次性容器里把整条链路真装一遍）：
      docker run --rm --name iot-e2e \
        -v /home/yhz/iot:/src:ro \
        -v "$PWD/test_e2e.sh":/e2e.sh:ro \
        ubuntu:22.04 bash /e2e.sh
      末尾显示「全部通过」即可。它会检查依赖是否齐全、后端能否启动、
      登录/权限/上传是否正常 —— 这些问题只有真装一遍才会暴露。

#
#   第七部分  部署约束（重要）
#
########################################################

  1. 一台机器 = 一套系统 = 一个账号。不要在同一台机器上装多套。
  2. 已离线打包（部署时零下载）：
     · Python wheel 四个版本（3.10/3.11/3.12/3.13，自动挑匹配的）
     · NiFi 容器镜像
     · 系统软件 deb（ubuntu 20.04/22.04/24.04 各一套）
     · SQL Server ODBC 驱动 + unixODBC 依赖闭包（ubuntu 20.04 / 22.04 / 24.04 各一整套）
       由 deploy-kit/prepare_odbc_assets.sh 生成。24.04 已在【断网容器】里端到端实测：
       离线装完后能真连 SQL Server 2019 并执行查询（select @@version 有返回）。
       （历史情况：早先只有 22.04 一套闭包，24.04 上需要联网 apt 一次；现已补齐。）
  3. 「系统软件」的三种来源顺序：
     · 已装好 → 跳过
     · 包内有本发行版离线 deb → dpkg 安装，零下载
     · 都没有 → 自动把 apt 源切到 https:// 后在线装（需放行 443）
     三者都不行时，由 IT 预装基础软件即可，安装程序会自动跳过这一步。
  4. 各站点数据库独立，同名账号在不同机器上是不同账号。
  5. 每台机器独立生成密钥（IOT_SECRET_KEY / META_XATTR_KEY），
     保存在 .deploy-secrets，请分别保管。
  6. 自助注册默认关闭，账号由部署脚本创建；如需新增账号请用
     add_factory.sh 或内部管理页。
  7. 离线包的覆盖边界（超出这个范围就需要联网或人工介入）：
     · 发行版：Ubuntu 20.04/22.04/24.04 有离线系统 deb；其他发行版走 apt（需网络）
     · SQL Server ODBC：Ubuntu 20.04 / 22.04 / 24.04 **都能纯离线装全**（依赖闭包各备一套，24.04 已断网实测）；
       其他发行版（如 Debian 12/13）走 apt（需网络）。其它数据源不需要 ODBC。
     · CPU 架构：仅 x86_64（aarch64/arm64 不在包内）
     · Python：仅 3.10~3.13；且应用要求 ≥3.9
     · 系统需为 systemd（服务用 systemd 托管）
     · 资源：内存 ≥8G，/home 剩余 ≥20G，docker 所在分区 ≥10G
     · 端口 5174/8081/8080/3306 需空闲
     · 如果机器只能通过「代理」上网，脚本的 HTTPS 自动切换帮不上忙，
       需要先配好 http_proxy/https_proxy 环境变量
